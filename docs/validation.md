## 从发现到复核

| 批次与命令 | 实测结果 | 业务含义 |
| --- | --- | --- |
| 45 条旧标注，用 v1 筛查 | 9 条 `COVERAGE_GAP`，英国 2 条、新加坡 2 条、澳洲 5 条 | 澳洲提出「补充装兼容性」后，英、新也找到当地同类案例 |
| 完全相同的 45 条旧标注，用 v2 筛查 | 相同 9 条为 `LABEL_MISMATCH` | 类别已经存在，这些记录仍用旧的「一般包装」标签 |
| 澳洲复核表，用 v1 校验 | 5 条新标签被拦截，退出 1 | 旧规则不接收新标签 |
| 澳洲复核表，用 v2 校验 | 通过，退出 0，兼容性 5 条 | 澳洲负责人只改了 5 条标签，原文和旧表保留 |
| v2 汇总三地复核后的批次 | 45 条通过，兼容性 9 条，续装筛查无剩余提示 | 同一分类在三地样例中都有可复核结果。区域负责人可分派后续核实 |

澳洲复核表在 v1 和 v2 的校验中输入指纹均为 `bdab67962844`。规则指纹从 `76f86e31bd5e` 变为 `0728e7536859`。比较的是同一份修订样例。

业务提案由**澳洲市场负责人**发起。英国、新加坡各用本地样例找出 2 条同类问题。**区域负责人**审核口径和影响后批准，**维护者**把批准的规则提交到 GitHub 并重新发布同一个环境。Skill 提供查找和证据整理，业务标签由人决定。

在仓库根目录可复跑：

```sh
python3 -m unittest -v
python3 feedback_review.py --rules rules/v1.json samples/uk.csv samples/sg.csv samples/au.csv
python3 feedback_review.py --rules rules/v2.json samples/uk.csv samples/sg.csv samples/au.csv
python3 scripts/check_team_cloud_environment.py --prepare
```

## Enterprise 共享验收

两人登录同一个 Enterprise 工作区，选择同一已发布环境，各开新任务。先直接运行 `python3 scripts/check_team_cloud_environment.py`，再各自调用 `check-market-feedback` 检查三地旧标注和复核表。任务直接读取发布的 v2 变量。记录实际输出，分别核对英国 2 条、新加坡 2 条、澳洲 5 条。

| 账号角色 | 环境名称与发布版本 | Git 提交和验收输出 | Skill 可见及运行记录 | 权限观察 |
| --- | --- | --- | --- | --- |
| A · 维护者 | 待填 | 待填 | 待填 | 验证发布或编辑 |
| B · 普通市场成员 | 待填 | 待填 | 待填 | 验证选择环境和启动任务 |

两人均需要选中同一发布版本、使用相同 Git 提交、通过验收并得到相同的 45 条汇总和 Skill 结果。之后进行完整五人交接，记录规则版本错误、上手时间和需要协助的次数。[发布步骤](setup.md)
